# Структура src

```
app/        маршруты expo-router — только реэкспорт экранов из pages/
pages/      экраны: композиция из модулей + локальные components/ и hooks/
modules/    домены (auth, programs, workout, social, bro) — вся логика здесь
shared/     то, что не знает о доменах: api-клиент, ui, lib, constants
theme/      токены дизайна
```

В каждой из этих папок и в их подпапках есть свой README — что там лежит и как этим пользоваться.

## Модуль

```
modules/<домен>/
  api/        по одной функции на эндпоинт: <имя>Api.ts
  models/     типы ответов бэка
  queries.ts  react-query: ключи кэша (<домен>Keys) и хуки
  store.ts    zustand — только клиентское состояние, без сети
  services/   сценарии: меняют стор, ставят операции в очередь, ходят в api
  helpers/    чистые функции домена
  components/ компоненты домена, которые нужны нескольким экранам
  index.ts    публичный API модуля — логика, без компонентов
  ui.ts       компоненты модуля
```

## Правила

- Снаружи модуль импортируется только через `@/modules/<домен>` (логика) и `@/modules/<домен>/ui` (компоненты); внутри модуля — относительными путями.
- Логика модуля не импортирует общий `@/shared/ui` — он тянет за собой компоненты и нативный UI.
- `shared` не импортирует `modules`; модули не импортируют `pages`.
- Серверные данные — только через `queries.ts`; в zustand — то, что живёт на устройстве.
- Компоненты вызывают сервисы и хуки, а не api напрямую.
