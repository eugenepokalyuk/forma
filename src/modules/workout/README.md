# workout — тренировка и офлайн-синхронизация

Во время тренировки источник правды — устройство: каждое действие сразу меняет
локальное состояние и ставит операцию в очередь, сеть ничего не блокирует.

- `services/workout.ts` — сценарии: `startWorkout`, `logSet`, `skipExercise`, `undoSet`,
  `replaceExercise`, `addExercise`, `hideExercise`, `completeWorkout` (вместе с оценкой и постом в ленту),
  `discardWorkout`; привязка/сброс данных при входе-выходе
- `hooks/useStartWorkout` — запуск с экрана (диалог «завершить текущую?» + переход)
- `store.ts` — активная тренировка (persist в MMKV)
- `sync/` — очередь операций (оценка и пост встают в неё до `complete` — после него
  серверный id сессии забывается) (`outbox.ts`), отправка (`sendOp.ts`), обработчик с backoff
  (`processOutbox.ts`), триггеры: сеть, фон, таймер (`useOutboxSync`); ход текущей отправки —
  `syncProgress.ts` (только в памяти); ушедшие `complete`/`discard` обновляют историю сессий
  (`useSessions`) — из неё итоги профиля и «Сегодня» на главной
- `helpers/exercisePicker.ts` — подбор из каталога (как на сайте): замены из админки,
  иначе по мышцам; поиск по началу слов; упражнение тренировки из позиции каталога
- `helpers/` — номер следующего подхода, подстановка веса/повторов, тоннаж, формат подходов,
  следующая по плану тренировка и пройденные дни (`getNextWorkout`, `getProgramProgress`)
- `queries.ts` — история сессий (`useSessions`)
- `ui` — `WorkoutExercises`: упражнения дня (превью, название, подходы) — страница программы и главная;
  `SyncProgressBar`: тонкая полоска под статус-баром, пока очередь отправляется дольше 0,4 с
  (смонтирована в корневом layout)
- `__tests__/` — сценарии очереди: офлайн, ошибки сервера, смена пользователя, дубли подходов

Тесты: `npm test`.

## Замена и добавление упражнения

Каталог упражнений (`useExerciseCatalog` из `programs`) держится в кэше на устройстве и
предзагружается на главной — выбирать можно без сети.

- **Замена** — только на эту тренировку: упражнение меняется на месте (тот же id), план
  остаётся. Подходы уходят с `actualCatalogExerciseId` (`ActiveSession.replacedCatalogIds`) —
  сервер пишет историю в упражнение-замену. Уже записанные подходы прежнего отменяются.
- **Добавление** — сразу после текущего, «только сегодня» или «каждый раз» (`persist`).
  Упражнение появляется сразу с локальным id; операция `addExercise` в очереди создаёт его на
  сервере, а `exerciseIds` подменяет локальный id в подходах при отправке.
- **Скрыть** можно только своё упражнение (`isCustom`), не последнее: подходы отменяются,
  `removeExercise` убирает его на сервере. Если оно ещё не ушло на сервер — его операции
  просто вычёркиваются из очереди.
